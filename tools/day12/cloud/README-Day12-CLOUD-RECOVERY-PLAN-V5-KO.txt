Day12 — 백업 위치와 저장 일관성 계획 v5 (2026-10-15)

v4 실제 결과에서 서버 경로 3/3과 OneDrive 접근이 확인되었습니다.
서버 원본이 OneDrive 안에 있다는 운영자 확인도 받았습니다. v4는 OneDrive 전체
폴더를 실제 목적지처럼 비교했으므로 포함 관계를 차단했습니다. v5는 아래를 나눕니다.

- 클라우드 상위 폴더: 서버가 그 안에 있는지는 배치 관찰 결과입니다.
- 실제 백업 후보: 원본과 다른 형제 폴더를 새 이름으로 제안하되 생성하지 않습니다.
- 로컬 작업 후보: 두 클라우드와 모든 원본/GSC 상태 폴더 밖에 있어야 합니다.

실행이 필요한 경우에만 ZIP 전체를 풀고
RUN_Day12_Cloud_Recovery_Plan_READ_ONLY.cmd를 한 번 실행합니다.
이미 Codex에서 실제 v5 계획 결과를 확인했다면 같은 검사를 반복할 필요가 없습니다.
클라우드 '상위 폴더'를 선택합니다. 실제 경로는 공유 JSON에 넣지 않습니다.
결과 폴더가 열리면 DAY12-CLOUD-RECOVERY-PLAN-V5-SHARE-ONLY-THIS.json만 공유합니다.

검사 범위:
- v4의 GSC config/localhost GET/OneDrive 발견 함수를 재사용합니다.
- 서버 폴더/서버 properties 존재 메타데이터와 폴더 핸들의 최종 이름만 읽습니다.
- junction과 부모 경로의 별칭을 비교하되, 클라우드 계정/동기화를 검증했다고 하지 않습니다.
- 없는 후보는 PLANNED_NOT_CREATED로 기록합니다. 기존 폴더/파일은 재사용하거나 덮어쓰지 않습니다.
- 기본 자동 계획은 이전에 확인한 G: 마운트 자체의 메타데이터만 확인합니다. 하위 폴더를
  열람하거나 시스템 폴더를 계정 폴더라고 추측하지 않습니다. G:는 의도한 Google 위치의
  미검증 후보이며 실제 공급자/계정/쓰기 권한은 증명하지 않습니다.
  OneDrive도 실제 접근 가능한 후보가 하나일 때 계획에만 사용하며 계정은 미검증입니다.
- 새 보고서와 임시 합성 테스트 파일 외에 서버/클라우드에 파일이나 폴더를 만들지 않습니다.
- 원본 위치, OneDrive 동기화 설정, 서버 상태, ACL, 방화벽을 바꾸지 않습니다.

PLAN_PATHS_REVIEW_REQUIRED는 경로 계획 검토 단계입니다. 실행 허용이나 백업 PASS가 아닙니다.
전체 서버 복구본에는 월드 외에 플러그인 상태/설정/JAR과 공용 상태까지 필요합니다.
save-off/save-all flush는 플러그인의 별도 저장 작업까지 멈춘다는 증거가 아닙니다.
Wild/Playground/Lobby는 향후 승인된 정상 종료와 무작성 상태, 또는 독립적으로 검증된
애플리케이션 정합성 스냅샷이 필요합니다. Other는 계속 OFFLINE으로 두고 작성자 부재를 확인해야 합니다.
느린 업로드 시간 동안 서버를 save-off 상태로 유지하는 절차는 사용하지 않습니다.

현재 GSC 기본 백업 ZIP의 해시/Verified 플래그는 암호화·공급자 전송·독립 다운로드·복원 증거가 아닙니다.
실제 원본 크기/로컬 캐시와 두 클라우드 여유 용량, 암호화와 키 복구, 파일 placeholder/외부 저장소,
일관성 경계, 새 복구본 보호/해시/독립 복원까지 확인해야 실행할 수 있습니다.
이 도구는 백업 API를 호출하거나 원본 파일을 재귀 탐색/복사하지 않습니다.
Google G: FAT32 표시는 실제 4GiB 파일 제한의 적용 여부를 아직 증명하지 않습니다.
같은 OneDrive 계정의 형제 폴더도 독립된 장애 영역은 아니므로 별도 Google 복사와 복원 시험이 필요합니다.

PR #53은 Draft이며 최종 Stable/운영 변경 게이트는 BLOCKED입니다.
BUILD-INFO-V5.json은 최신 소스 커밋과 파일 해시입니다. CI PASS는 실서버 백업 완료를 뜻하지 않습니다.
