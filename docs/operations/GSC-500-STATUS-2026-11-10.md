- 외부 구성요소 Staging 응답 대기/다운로드 제한, 실패 원인 기록, 중복 실행 보호, SHA-256 검증과 기존 파일 복구 경로 보완. Geyser 업데이트를 기존 Velocity **3개 프록시**에 적용한 뒤 로컬 Java/Bedrock 상태 검사 통과.
- Windows의 잠긴 `session.lock` 때문에 온라인 월드 백업이 실패하던 오류 수정. **실제 월드 데이터 잠금 오류는 무시하지 않습니다.** 로비·야생·놀이터 월드 ZIP/해시 검증, 로비 백업 91개 파일의 *별도 폴더 추출·해시 재검증* 통과. 이는 실월드 복원이 아닙니다.
- **백엔드 4개**(야생·놀이터·기타·로비), **Velocity 프록시 3개**의 기존 구조를 유지. 2026-11-08 마지막 로컬 관찰 상태는 야생·놀이터·로비 온라인, 기타는 의도적으로 오프라인. 네 번째 프록시를 추가하거나 월드·플레이어 데이터를 초기화하지 않았습니다.
- 문제가 있던 `AutoSaveWorld`는 세 서버의 플러그인 로딩 경로에서 제거하여 **복구 가능한 로컬 격리 백업**에 보존했습니다. Paper의 기본 자동 저장은 유지하고 GSC 백업을 수동 실행해 성공 확인. 이전 플러그인 백업 파일과 설정은 삭제하지 않았습니다.
- 초기 2시간 단위 백업은 놀이터 ZIP이 회당 약 3.14GiB여서 저장 공간 소진 위험이 확인됨. 24개의 GSC 예약 작업을 보존하면서 **4개 활성 / 20개 비활성화**로 조정: 야생 06:00·18:00, 놀이터 06:10·18:10. 기존 백업 삭제 없음. 예약의 **미래 정시 자동 실행은 별도 미검증**이며, 오래된 백업을 Trash로 옮기는 정책은 **디스크 용량을 즉시 회수하지 않음**.

## 완료 및 남은 과제

**개인용 현재 사용 목표:** 운영자 실플레이 정상 보고까지 달성. **전면적인 E2E/정식 운영 게이트 통과 선언은 아님.**

앞으로 실제로 필요한 경우에만 다룰 항목: 백업 Trash 용량 및 디스크 모니터링, 예약의 실시간 자동 실행 확인, 모바일 GSCM·외부 WAN/NAT 인증, 장시간 다인 플레이·부하, 재부팅 뒤 서버 상태 및 실제 라이브 복원. 인게임 기능이 정상이라면 불필요한 재설치/반복 테스트/서버 재시작을 진행하지 않습니다.

**저장 원칙:** 개인정보, 인증 토큰, 공개키가 아닌 비밀키, 실제 월드 데이터·플레이어 데이터·서버 전체 설정·로그·백업 ZIP을 GitHub에 커밋하지 않습니다. 증거는 공개 가능한 요약과 PR/CI 링크로 한정합니다.
