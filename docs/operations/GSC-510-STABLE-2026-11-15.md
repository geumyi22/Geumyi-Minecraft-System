## 제공 기능과 검증 범위

- Paper / Spigot / Purpur / Vanilla / Fabric / Forge / NeoForge 등 **7종 게임 서버** 공식 설치·등록·콘솔·상태·정상 종료·재시작. 새 GSC 관리 Velocity까지 **8종 설치 경로**.
- 자동 Java 및 일부 설치 도구 준비, 기존 폴더 가져오기, 파일을 삭제하지 않는 등록 해제, 중지 상태의 설정 편집을 구현. 과거 5.0 관리 기능과 세계·플레이어 데이터 보호를 유지하도록 설계.
- **새 GSC 소유 Velocity**의 시작·정상 종료·재시작과 새 서버 연결. 기존 `wild/playground/other` Velocity **3개는 Windows Scheduled Tasks가 계속 소유**합니다. 운영 프록시에서 GSC 종료 브리지를 사용하려면 **기존 방식으로 한 번 안전하게 정상 종료한 뒤 오프라인 플러그인/인증 설정을 준비**해야 합니다. 이번 릴리스로 운영 중인 기존 프록시가 자동 전환되는 것은 아닙니다.
- [5.1 개발 QA](https://github.com/geumyi22/Geumyi-Minecraft-System/blob/release/gsc-5.1.0-personal-20261115/docs/releases/GSC-5.1.0-QA.md)에 테스트 전용 디렉터리에서 7종 게임 서버 + 새 Velocity 설치·기동·자동 프로토콜 클라이언트 월드 진입·저장·재시작·종료 및 제어 브리지 인증·PID 검증 결과를 구분해 기록했습니다. **실제 Microsoft 계정으로 사람이 플레이한 검사는 아닙니다.**
- 기존 GitHub Windows CI의 경로 별칭(`RUNNER~1`)에 따른 임시 테스트 경로 비교 실패를 수정했습니다. 운영용 경로 이탈·보안 검사 코드를 완화하거나 삭제하지 않고 테스트 fixture를 실제 등록 경로와 같은 정규화된 경로로 생성했습니다. 이후 [수정 CI #43618596986](https://github.com/geumyi22/Geumyi-Minecraft-System/actions/runs/43618596986) SUCCESS, **정확한 릴리스 소스 CI #43619416741도 SUCCESS**.
- 릴리스 전용 워크플로가 정확한 `GITHUB_SHA` 대상으로 재빌드·검증하고, 기존 신뢰 Ed25519 개인키(Secrets 보존)를 이용해 서명한 후, GitHub Draft를 만들고 다운로드한 파일을 다시 검증했습니다. **검증된 Draft만 공개**했으며 5.0.0 자산은 덮어쓰지 않았습니다.

## 운영 PC 설치 상태와 남은 QA

**이번 GitHub 게시 작업에서 실제 기존 Windows 운영 PC의 GSC 5.0.0을 GSC 5.1.0으로 교체하지 않았습니다.** 원격 PC가 연결되지 않은 상태의 소스·CI·릴리스 작업이므로 실행 중 서버/월드/플레이어 데이터·Windows Scheduler·설정·백업을 변경하지 않았습니다.

개인 PC에서 사용하는 5.0.0 유지보수판의 실플레이 PASS 기록과 5.1.0의 실제 설치/실플레이는 별개입니다. 실제 운영 업그레이드는 먼저 백업, 설치 역할/파일/설정 확인, Windows 서비스 중지/재시작 시 안전성, 롤백 경로 검증 후 진행해야 하며, 오류가 있으면 5.0 상태를 유지합니다. 안전 검사를 우회하는 강제 설치·프로세스 종료는 금지합니다.

**추가 미검증:** 실제 Microsoft 계정 Java/Bedrock 로그인, 운영 프록시 3개의 제어 연결·정상 종료·재시작·플레이어 이동, WAN/GSCM 실기기 인증, 장시간 멀티플레이·부하, 기존 월드의 실복원 및 운영 PC 5.1 실설치. 정식 프로젝트 전체 Day12 게이트는 변경하지 않았습니다.
