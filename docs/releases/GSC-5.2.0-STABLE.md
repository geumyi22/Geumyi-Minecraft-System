# GSC 5.2.0 · 개인용 Stable

GSC Client 왼쪽 메뉴의 **설정** 아래에 경고 아이콘이 있는 **위험 작업** 항목을 추가했습니다. 이 화면에서 현재 Windows PC의 GSC Host 시작 유형과 Client 로그인 자동 실행 상태를 새로고침할 수 있습니다. **운영 모드 관리자 열기**를 누르면 GMS Operating Mode 창에서 상세 검사, 수동 모드 적용, 원래 설정 복원을 진행합니다.

| 필요한 작업 | 여는 방법 |
|---|---|
| GSC에서 시작 상태 확인 | **위험 작업 → GMS 운영 모드** |
| 자동 시작 항목 상세 검사·변경 | **운영 모드 관리자 열기**로 전체 기능 열기. **수동 전환 미리보기**와 **기존 설정 복원 확인**으로 각 작업의 확인 화면 바로 열기 |
| GSC를 실행하지 않고 사용 | 릴리스 자산의 `GMS_OperatingMode_v3.0.1.exe`를 해당 Windows PC에서 직접 실행 |

관리 대상은 도구를 실행한 PC입니다. 관리 PC에서 원격 Host에 연결해 쓰고 있다면 서버 PC의 부팅 동작은 서버 PC에서 확인하세요. 수동 모드 적용과 복원은 운영 모드 관리자에서 권한을 승인하고 변경 대상을 확인한 뒤 진행합니다. 이미 실행 중인 Minecraft 서버와 프록시는 플레이어 접속과 저장 상태를 확인해 정상 종료하세요.

## 설치와 업그레이드

처음 전환할 때는 PC 역할에 맞는 절차와 복원 순서를 확인하세요. [사용자 설명서](https://github.com/geumyi22/Geumyi-Minecraft-System/blob/gsc-v5.2.0/docs/releases/gsc-5.2.0/OPERATORS.md) · [실제 PC 검증 체크리스트](https://github.com/geumyi22/Geumyi-Minecraft-System/blob/gsc-v5.2.0/docs/releases/gsc-5.2.0/PC-CHECKLIST.md)

- Windows x64 설치 파일은 `GeumyiServerCenter-v5.2.0-Setup.exe`입니다. Host와 Client의 제품 버전은 5.2.0이며 운영 모드 도구의 버전은 3.0.1입니다.
- 기존 서비스가 있는 서버 PC에서는 Setup이 실행 중인 Host의 Health와 서비스 여부, API 세대 4를 확인합니다. 허용 버전은 4.5.1, 5.0.0, 5.1.0, 5.1.1, 5.2.0입니다. 저장된 역할에 버전이 있으면 실행 중인 버전과도 대조합니다.
- 설치 전에 월드·플레이어 데이터와 설정을 백업하세요. 5.2.0 Setup은 자신이 변경할 GSC 서비스·로그인 시작 값·구형 작업이 운영 모드 복원 기록에 있거나 전환이 중단된 경우 작업을 보류합니다. 운영 가능한 점검 시간에 같은 PC·계정의 관리자에서 **중단된 작업 복구** 또는 **기존 모드 복원**을 완료하세요. 복원이 시간 기반 예약 작업을 즉시 실행할 수 있으므로 미리보기를 먼저 확인하세요.
- 서버 역할 업그레이드는 기존 Host의 실행 상태를 확인합니다. 복원 후에도 Host가 중지돼 있으면 수동 시작하고 정상 상태를 확인한 다음 Setup을 실행하세요. 대화형 Setup은 서버 역할에서 자동(지연 시작) Host 서비스를 구성하고 Client 역할에서 **트레이 자동 실행** 선택을 반영합니다. 수동 운영을 이어갈 경우 **재부팅 전에** 다시 검사하고 수동 모드를 적용하세요.
- Host를 재시작하는 자체 업데이트에도 복원 기록 보호가 적용됩니다. Client 파일만 교체하는 자체 업데이트는 시작 설정을 유지합니다. 이 보호는 5.2.0 설치기에 포함됩니다.

기존 GSC Client와 GSCM이 호출하는 Host API 경로와 API 세대 4는 유지합니다. 새 운영 모드 메뉴와 실행 요청은 5.2.0 Windows Client가 처리합니다. 서버의 Host만 업데이트한 경우에는 사용하는 PC의 Client도 5.2.0으로 업데이트해야 메뉴가 표시됩니다.

동반 도구 3.0.1은 GSC가 Windows DPAPI로 보호해 저장한 API 토큰을 정상 종료 요청에 사용할 수 있습니다. 복호화가 실패하면 요청을 보류합니다. 기존 3.0.0의 전환·복원 기록을 이어서 사용합니다.

Windows 작업 스케줄러가 예약 작업 XML의 기본값과 순서를 다르게 표시해 정상적인 트리거 변경도 충돌로 판정하던 문제를 수정했습니다. 수동 전환은 예약 작업의 자동 트리거를 끄고, 복원은 해당 작업의 기존 트리거 상태를 되돌립니다.

## 기존 기능 오류 수정

- 같은 서버를 같은 초에 여러 번 백업해도 각 ZIP이 다른 이름으로 저장됩니다. 보관 정책은 생성 시각을 더 정밀하게 비교해 최신 백업을 유지합니다.
- 백업 휴지통 이동·복원 시 목적지에 같은 이름의 ZIP, 체크섬 또는 보호 기록이 있으면 이동을 보류합니다. 보호 기록을 읽을 수 없는 백업도 자동 정리 대상에서 제외합니다.
- 복원 전에 ZIP 내부 파일과 백업에 기록된 월드·설정 범위를 대조합니다. 현재 월드 체크포인트에 저장되지 않은 기존 폴더나 서버 폴더 아래의 링크·정션을 통해 다른 위치에 쓰게 되는 경로는 보류합니다.
- Setup 설치·자체 업데이트와 Host의 백업 복원·설정 갱신은 교체할 파일을 고유한 임시 파일에 먼저 씁니다. 복사 실패나 파일 잠금으로 교체에 실패해도 이전 파일과 같은 폴더의 기존 임시 파일을 보존합니다.
- Host에 제어 작업이 동시에 들어올 때 대기열 끝에 남은 요청도 처리합니다. 최근 작업 500건을 정리할 때 실행 중인 작업은 상태 목록에 유지합니다.
- Client와 Host 콘솔은 서버 응답을 기다리는 중에 작성한 명령과 그동안 추가된 로그를 보존합니다.

## 배포 파일 확인

`deployment-stable.json`과 `.sig`는 프로젝트 배포 키로 서명한 메타데이터입니다. `SHA256SUMS.txt`에서 파일별 해시를, `GSC-PERSONAL-PROVENANCE.json`에서 정확한 소스 커밋과 CI 실행을 확인할 수 있습니다. Windows EXE의 Authenticode 서명은 제공하지 않습니다.

이 릴리스의 검증 범위는 Windows 빌드와 격리 환경 회귀 시험입니다. 운영 서버의 설치, UAC 승인, 실제 자동 시작 차단·복원, 재부팅, 월드 저장과 플레이어 접속은 해당 PC에서 별도로 확인해야 합니다. GSCM과 연동 플러그인의 버전, 기존 세 Velocity 프록시의 작업 스케줄러 소유권은 기존 계약을 따릅니다. [이전 5.1.1 Stable](https://github.com/geumyi22/Geumyi-Minecraft-System/releases/tag/gsc-v5.1.1)
