# GSC 5.2.0 운영 모드 사용자 설명서

Windows 11 x64에서 GSC와 Minecraft를 필요할 때만 켜려면, **서버가 설치된 PC에서 시작 설정을 전환**한 뒤 **실행 중인 서버를 정상 종료**하세요. GSC Client 5.2.0과 독립 실행 파일은 같은 GMS Operating Mode 3.0.1 창을 엽니다.

## 어느 PC에서 열까요?

| 사용하는 PC | 여는 방법 | 확인할 대상 |
|---|---|---|
| 서버 전용 PC | `GMS_OperatingMode_v3.0.1.exe` 직접 실행 | 이 PC의 Host, 서버, Agent, 프록시와 예약 작업 |
| 본컴 / 원격 관리 PC | GSC Client 왼쪽 **설정** 아래 **⚠ 위험 작업** | 이 PC의 Client 로그인 자동 실행. 원격 Host의 부팅 설정은 해당 서버 PC에서 확인 |
| 서버와 Client를 함께 쓰는 PC | **⚠ 위험 작업** 또는 독립 EXE | 이 PC의 Host 서비스와 현재 계정의 Client 로그인 자동 실행, 서버 관련 시작 경로 |

GSC 전체 설치 파일은 `GeumyiServerCenter-v5.2.0-Setup.exe`입니다. 기존 서버 역할을 유지해 업그레이드할 때는 아래의 **업데이트 후에도 수동 운영을 유지하려면**을 먼저 확인하세요. 설치를 변경할 필요가 없으면 해당 PC에서 독립 EXE를 열 수 있습니다.

## GSC에서 여는 세 가지 방법

**⚠ 위험 작업 → GMS 운영 모드 → 현재 PC의 시작 설정**에서 **새로고침**을 누르면 **GSC Host 서비스 시작 유형**과 **GSC Client 로그인 자동 실행**을 읽습니다. 실제 부팅 후 어떤 프로그램이 실행됐는지는 별도로 확인합니다.

| 버튼 | 열리는 화면 |
|---|---|
| **운영 모드 관리자 열기** | 전체 검사 결과와 정상 종료·수동 시작·복구 도구 |
| **수동 전환 미리보기** | 현재 권한에서 식별된 전환 후보. **관리자 권한으로 검토**하면 다시 검사하고 최종 변경 목록을 표시 |
| **기존 설정 복원 확인** | 이 계정의 저장된 원래 값과 대조하는 복원 절차. 관리자 창의 **기존 모드 복원**에서 확정 |

**사용 불가**가 표시되면 안내 메시지를 확인하세요. GSC는 설치 위치에 있는 동반 EXE의 무결성을 확인합니다. 공식 배포 파일을 대조하고 5.2.0 Setup으로 복구하거나 배포받은 독립 EXE를 직접 여세요.

## 수동 모드로 전환하고 정상 종료하기

1. 점검 시간을 정하고 접속자에게 안내하세요. 최근 월드와 플레이어 데이터의 복구 가능한 백업을 확인한 뒤, 현재 Host 시작 유형, Client 자동 실행, 사용 중인 프록시와 주요 예약 시간을 기록하세요. 운영 모드 관리자가 백업하는 것은 **변경 대상 시작 설정**입니다.
2. 운영 모드 관리자에서 **자동 실행** 탭의 **판정**, **예정 변경**, **식별 근거**를 확인하세요. 행을 두 번 누르면 세부 내역이 열립니다. **실행 상태 · 확인 필요**에는 실행 중인 프로세스, 추가 확인 사항, 검사 경로가 나옵니다. 빠진 GMS 전용 폴더가 있다면 **서버 폴더 추가**로 `server.properties` 또는 `velocity.toml`이 있는 폴더를 선택하세요.
3. 평소 운영에 쓰는 **같은 Windows 계정**으로 **관리자 권한으로 열기**를 승인하세요. **수동 모드 전환**의 최종 목록을 확인하고 적용합니다. 취소하면 변경하지 않습니다. 설치 경로와 시작 명령을 식별한 자동 서비스는 수동으로 전환하고, 예약 작업은 활성 트리거를 해제합니다. 식별된 Run 값과 시작 폴더 항목은 원상 복구할 수 있도록 보관합니다.
4. 완료 메시지 후 **백업 · 복구**에서 보관된 복원 대상과 상태를 확인하세요. **조회** 또는 **확인 필요**로 남은 항목은 해당 서비스·작업의 실행 경로와 원래 관리 화면에서 확인하세요. 다른 Windows 계정의 시작 항목, 그룹 정책이나 별도 감독 프로그램이 있다면 그 관리 위치에서도 점검하세요.
5. 플레이어 접속 종료를 확인한 뒤 **Host 정상 종료**를 실행하세요. 공식 로컬 GSC Host와 연결해 저장·종료가 끝날 때까지 기다립니다. 개인 서버·프록시나 설치 작업 때문에 요청이 거절되면 GSC에서 해당 작업을 마치고 인스턴스를 정상 종료한 뒤 재시도하세요. Host 인증 정보를 확인할 수 없다는 메시지가 나오면 원래 GSC에서 종료하세요.
6. 독립 Minecraft 서버는 해당 서버 콘솔의 `stop`, 독립 Velocity는 해당 프록시 콘솔의 `shutdown`으로 종료하세요. GSC Client는 트레이에서 종료합니다. 서버 저장 로그, StatusAgent 종료, 별도 Discord 전송 작업을 확인하세요. Host 버전에 따라 Agent의 정상 종료가 실패하면 Host가 Agent 종료를 강제할 수 있습니다.
7. 독립 EXE에서 **다시 검사**하고 승인된 시점에 재부팅하세요. 로그인 직후와 지연 시작 시간이 지난 후, 등록된 일정 시각에 각각 관찰하세요. 도구의 **변경 가능 0건**은 현재 검사 범위의 결과입니다. 실제 부팅 결과와 Discord 전송 여부는 함께 제공한 점검표에 적으세요.

## 필요한 날에 시작하거나 원래 운영으로 돌아가기

- **이번에만 시작**하려면 서버 PC의 운영 모드 관리자에서 **Host 수동 시작**을 누르세요. 확인된 GSC Host 서비스를 시작합니다. Host 구성에 따라 서버·StatusAgent·Discord 전송도 함께 시작될 수 있습니다. 별도 프록시나 개인 서버는 원래 관리 화면에서 필요한 항목을 시작하세요.
- **원래 시작 설정으로 복원**하려면 적용했던 PC·계정에서 **기존 모드 복원**을 열고 목록을 검토하세요. 복원은 도구가 보관한 원래 값을 사용합니다. 다시 활성화한 예약 작업은 놓친 일정이나 현재 조건 때문에 즉시 실행될 수 있으므로 점검 시간에 확정하세요. 완료 후 **다시 검사**하여 처음 기록한 값과 대조하세요.
- **전환 도중 중단**돼 **중단된 작업 복구**가 나타나면 이를 먼저 실행하세요. 마지막 전환 시도 직전으로 되돌린 후 재검사합니다. 외부에서 값이 바뀌어 충돌하면 상태와 로그를 보관하고, 해당 서비스 또는 작업의 현재 정의를 확인하세요. 복구 폴더나 원래 항목을 수동으로 삭제하면 이후 자동 복원에 필요한 기록을 잃을 수 있습니다.

## 업데이트 후에도 수동 운영을 유지하려면

1. 5.2.0 Setup은 변경할 GSC 시작 항목이 기존 복원 기록에 있거나 전환이 중단된 경우 설치를 보류합니다. 같은 PC·계정에서 **중단된 작업 복구**가 보이면 먼저 실행하고, 필요한 경우 **기존 모드 복원**으로 원래 상태를 돌리세요.
2. 기존 Host 서비스가 있는 서버 PC는 실행 중인 Host의 상태를 확인받습니다. 복원한 Host가 중지 상태이면 **Host 수동 시작** 후 정상 상태를 확인하고 이전과 같은 역할로 Setup을 실행하세요. 5.2.0 설치기가 확인하는 기존 Host 버전은 4.5.1, 5.0.0, 5.1.0, 5.1.1, 5.2.0이며 Host API 세대는 4입니다.
3. 서버 역할은 설치 과정에서 Host를 자동(지연 시작) 서비스로 구성하고, Client 역할은 **트레이 자동 실행** 선택을 반영합니다. 수동 운영을 계속하려면 **다음 재부팅 전 다시 검사하고 수동 모드를 적용**한 뒤 원하는 서버만 정상 종료하세요. Host를 재시작하는 자체 업데이트에도 복원 기록 보호가 적용됩니다. Client 파일만 갱신하는 자체 업데이트는 시작 설정을 변경하지 않습니다.

## 오류 기록 찾기

**백업 · 복구** 탭 아래의 **백업 위치**와 **진단 로그**를 확인하세요. 일반 권한 로그는 `%LOCALAPPDATA%\GMS Operating Mode\Logs`, 관리자 로그와 전환 기록은 `%ProgramFiles%\GMS Operating Mode Recovery v3`에 있습니다. 오류 창에도 기록된 로그 경로가 표시됩니다. 문의할 때는 발생 시각, 선택한 작업, 오류 문구, PC 역할을 적고 인증 토큰과 개인 접속 정보는 제외하세요.

이미 실행 중이라는 안내가 나오면 기존 관리자 창을 사용하세요. v2 창이 감지되면 **v2 창 표시**로 원래 창을 확인해 정상 종료하세요. v2 복구 기록이 남아 있으면 v2에서 원래 모드를 먼저 복구하세요. 3.0.1은 3.0.0이 작성한 복구 기록을 같은 PC·계정에서 이어서 사용합니다.
