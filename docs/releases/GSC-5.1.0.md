# GSC 5.1.0 개인용 개발본 사용 안내

> **이후 업데이트 (2026-11-15):** [GSC 5.1.0 — 개인용 Stable](https://github.com/geumyi22/Geumyi-Minecraft-System/releases/tag/gsc-v5.1.0) 정식 게시. 정확한 릴리스 커밋 `a3f24700049ac99b5fb2b66e5fe8bc441f389a1d`의 Windows CI 및 서명 검증은 [21/21 SUCCESS](https://github.com/geumyi22/Geumyi-Minecraft-System/actions/runs/43619416741). 아래 초기 개발본 경고/이전 CI 실패는 **게시 전의 역사적 상태**이며, 운영 PC 5.1 설치·실제 계정 플레이·기존 Scheduler 프록시 전환은 여전히 미검증입니다. [릴리스 QA·설치 주의사항](https://github.com/geumyi22/Geumyi-Minecraft-System/blob/main/docs/operations/GSC-510-STABLE-2026-11-15.md).

서버 7종과 Velocity를 새로 만들고, 같은 화면에서 시작·정상 종료·재시작할 수 있는 개인용 개발본입니다. 기존 Paper 서버 4개, 월드·플레이어 데이터, 기존 Velocity 예약 작업 3개는 이번 개발과 확인 작업에서 변경하지 않았습니다. 운영 설치본을 교체하거나 배포한 상태는 아닙니다.

**이 버전은 현재 개발용 초안입니다.** [PR #64](https://github.com/geumyi22/Geumyi-Minecraft-System/pull/64)의 최초 5.1 기능 커밋 `d119d1ea70f11894e45fb1ec808dbc7b1256db1d`에 대한 GitHub Windows CI와 Day 11 Host 테스트는 **실패**했습니다. 개발 PC의 로컬 기능 QA 기록은 있으나 모든 환경에서 성공했다고 보장할 수 없으며 **아직 운영 서버에 설치하거나 공개 Stable로 배포하지 않았습니다.**

## 가장 빠르게 시작하기

1. 패키지를 새 폴더에 풀고 `Start-Personal.cmd`를 실행합니다. 처음에는 별도 `data` 폴더와 빈 서버 목록을 사용합니다.
2. **서버 → 서버 추가 → 새 서버 만들기**를 선택합니다. 추가 화면의 **새로 만들기** 탭에서도 같은 기능을 사용할 수 있습니다.
3. 서버 종류·이름·버전을 고르고, Minecraft EULA를 읽은 뒤 동의 여부를 직접 선택합니다.
4. **다운로드하고 만들기**를 누릅니다. Java·저장 폴더·사용하지 않는 포트는 기본값으로 자동 준비합니다. 지정하고 싶은 항목만 **고급 설정**에서 바꾸면 됩니다.
5. 생성이 완료되면 서버 카드의 **시작**을 누릅니다. 생성 완료만으로 서버가 자동 실행되지는 않습니다. **콘솔 · 로그**에서 준비 완료 메시지와 접속 포트를 확인하세요.

## 지원하는 종류

| 메뉴 | 종류 | 새로 만들기 |
|---|---|---|
| 서버 | Paper · Purpur · Vanilla | 공식 배포 파일 다운로드와 기본 설정 |
| 서버 | Spigot | 공식 BuildTools로 서버 JAR 생성. 첫 설치는 다른 종류보다 오래 걸릴 수 있습니다. |
| 서버 | Fabric · Forge · NeoForge | 공식 로더와 서버 설치. 추가 모드는 별도로 넣습니다. |
| 프록시 | Velocity | 공식 배포 파일과 새 프록시 설정 생성. GSC가 직접 실행합니다. |

**기존 서버 가져오기**는 준비된 폴더와 JAR 또는 실행 스크립트를 목록에 등록합니다. 기존 설정과 월드를 자동 변경하거나 서버를 자동 실행하지 않습니다. 기존 GSC Paper의 GDS·백업·원격 관리 기능은 **GSC 연동 서버 등록** 경로를 사용합니다. 새 서버 관리 기능이 기존 연동 기능을 모든 서버 종류에 자동 설치하는 것은 아닙니다.

## Java와 설치 도구

호환되는 Java가 있으면 이를 사용하고, 없으면 공식 Eclipse Temurin 배포를 `data/java-runtimes`에 준비합니다. 시스템 Java 설치·기본 PATH·JAVA_HOME 설정은 바꾸지 않습니다. 직접 지정하려면 고급 설정의 Java 실행 파일에 `java.exe` 전체 경로를 입력하세요.

Spigot에 필요한 Git 환경이 없으면 공식 PortableGit을 GSC 데이터 안에 별도로 준비합니다. 시스템 Git 설정은 유지합니다. Java·Git·서버 파일의 최초 준비에는 인터넷 연결과 추가 디스크 공간이 필요합니다.

## 새 Velocity와 게임 서버 연결하기

1. 게임 서버를 새로 만들 때 **이 PC의 프록시를 통해 접속**을 선택합니다.
2. 이 선택은 **새 서버의 설정 파일에만** `server-ip=127.0.0.1`, `online-mode=false`를 기록합니다. 게임 서버의 직접 접속은 이 PC 안으로 제한하고, 새 프록시가 계정 인증을 담당합니다. 가져온 서버에는 자동 적용하지 않습니다.
3. **프록시 → 새 Velocity 만들기**에서 버전을 선택합니다. 연결할 게임 서버 목록에 방금 만든 서버가 있으면 선택하고, 없으면 `주소:포트`를 직접 입력합니다.
4. 게임 서버와 프록시를 각각 시작한 뒤, Minecraft에서는 **프록시의 접속 포트**로 접속합니다. 외부 접속을 위한 공유기·방화벽 설정은 자동 변경하지 않습니다.

새 프록시는 기본적으로 `player-info-forwarding-mode=none`을 사용합니다. 원래 플레이어 UUID·IP를 게임 서버에 전달하는 설정까지 자동 구성하지 않습니다. 이 간단한 연결 방식은 새 서버용이며, 기존 월드·플레이어 데이터를 사용하는 서버를 이 방식으로 전환하지 마세요.

새 Velocity는 GSC가 직접 실행하므로 아래의 기존 예약 작업용 **종료 연결 준비**가 필요하지 않습니다.

## 기존 Velocity 3개 연결하기

기존 wild·playground·other 프록시의 실행 주체는 계속 Windows 작업 스케줄러입니다. **기존 Velocity 찾기**는 등록 후보를 찾는 기능이며, 등록만으로 실행 중인 프록시를 종료하거나 소유권을 가져오지 않습니다.

1. **프록시 → 기존 Velocity 찾기**에서 필요한 항목을 등록합니다.
2. 해당 프록시를 기존 콘솔의 `shutdown` 또는 기존 운영 방식으로 정상 종료합니다.
3. 완전히 중지된 상태에서 **종료 연결 준비**를 누릅니다. 필요한 제어 플러그인과 별도 인증 파일을 만들며, 내용이 다른 기존 파일을 덮어쓰지 않습니다.
4. **시작**을 누르면 동일한 기존 예약 작업을 실행합니다. 연결을 확인한 뒤 접속자 0명일 때 **정상 종료·재시작**을 사용할 수 있습니다.

실제 종료를 확인하지 못하면 강제 종료하거나 다음 실행을 진행하지 않습니다. 작업 정의·자동 복구 정책·기존 서버 설정은 변경하지 않습니다. 이번 확인에서는 운영 예약 작업 실행과 실제 운영 프록시 전환을 수행하지 않았습니다.

인증 파일인 `data/instance-secrets`와 프록시의 `plugins/gscvelocitycontrol/control.properties`는 공개하거나 공유하지 마세요. 로컬 제어 포트는 외부 개방이 필요하지 않습니다.

## 사용 중 알아둘 점

- **정상 종료**는 게임 서버에 `stop`, GSC 소유 Velocity에 `shutdown`을 보내고 실제 종료를 기다립니다. 재시작도 종료 확인 후에만 진행합니다.
- **등록 해제**는 목록에서만 제거하며 서버 폴더·월드·플레이어 파일을 삭제하지 않습니다. 설정 편집은 중지 상태에서 사용합니다.
- GSC 밖에서 이미 실행 중인 서버는 **외부 실행 중**으로 표시하며 중복 시작하지 않습니다. 원래 실행한 콘솔에서 종료한 뒤 다시 시작하세요.
- Host를 완전히 종료하기 전에 GSC로 실행한 게임 서버와 새 Velocity부터 정상 종료하세요. 이번에 추가한 새 서버 관리 기능은 강제 종료로 전환하지 않습니다. 원본 GSC 연동 서버의 기존 강제 종료 기능은 유지됩니다.
- Forge·NeoForge 기본 실행 파일은 로더 인수 파일을 유지하면서 선택한 Java·메모리를 사용합니다. 별도의 사용자 실행 스크립트는 그 스크립트의 메모리 설정을 사용합니다.
- 추가 모드와 모드팩은 직접 준비해야 합니다. 서버 종류·Minecraft 버전·로더·모드 의존성의 조합까지 자동 판정하지 않습니다.
- 설치 실패 시 기존 서버는 그대로 두고 생성 폴더와 로그를 남깁니다. 실패 폴더를 기존 서버 폴더 위에 덮어쓰지 마세요.

먼저 새 서버 하나에서 시작 → 접속 → 콘솔 확인 → 정상 종료 → 재시작을 확인하면 됩니다. 7종 게임 서버의 실제 기동·자동 클라이언트 월드 진입·재시작과 새 Velocity의 백엔드 경유 접속을 확인했습니다. 실제 계정 인증과 외부 접속 등 남은 확인 범위는 [검증기록](GSC-5.1.0-QA.md)에 구분했습니다.

`77647c6`은 출발한 5.0 유지보수 **기반 커밋**이며, 5.1 기능을 처음 커밋한 GitHub 버전은 `d119d1ea70f11894e45fb1ec808dbc7b1256db1d`입니다. 개발 브랜치는 `feature/personal-server-manager`입니다. 소스는 해당 개발 브랜치로 관리하며, GitHub 반영과 운영 배포는 별도입니다. 운영 설치본은 교체하지 않았습니다. 소스 빌드는 [BUILD.md](../../GSC/ServerCenter/BUILD.md), 개인용 실행 스크립트는 [tools/gsc5/personal](../../tools/gsc5/personal/)을 참고하세요. 실행 패키지에는 전체 변경 패치와 별도 빌드 안내도 포함합니다.
